    Destination trace implementation and validation

    Date: 25 October 2026 (Australia/Sydney). Working tree based on 99dc1448, extending the average SNR implementation.

    Behaviour

    !hillvue trace 4df5 resolves exactly four case-insensitive hexadecimal characters against full public keys in the verified, named repeater-advert cache. One match selects that identity; no match or multiple matches produce an unknown/ambiguous repeater error without transmitting discovery. Invalid syntax is ignored like other invalid bot commands. Bare trace is preserved.

    The sensor originates a standard authenticated flooded base-telemetry request. It discovers a fresh outbound path, appends the selected target and reverses the intermediate path to construct the loop back to itself. Direct neighbours and one through ten repeaters including the target are supported, with one- or two-byte path hashes. Unsupported request widths fail before discovery; unsupported/oversized returned paths are never probed.

    The public report remains Trace: <elapsed> ms RTT (avg SNR), with each node listed once from sensor to target, paired directional averages, and no separate return-node list. RTT begins at actual loop TX start; discovery, settling and queue time are excluded. Retry and original-route fallback reuse the existing probe and immutable report-delivery policies.

    The target must already recognise/permit the sensor identity. The bot does not log in, add ACL entries or grant permissions. Missing responses report discovery timeout, not that the target is unreachable. Unknown remote identity, permissions, clock replay checks, congestion and RF conditions may all prevent discovery.

    State and ownership

    • One transaction remains busy through discovery, tracing and bounded reporting. There are at most two discovery submissions and two trace submissions. Discovery admission is bounded to ten seconds per attempt, with the existing 250/500/1000 ms backoff and bounded jitter. Its receive timeout uses the ten-repeater airtime allowance, starting at TX start (at least 30 seconds).
    • Discovery tags come from getCurrentTimeUnique(), independently of random trace identifiers. Authenticated PATH data must match the selected full key, a transmitted discovery tag and the captured discovery scope.
    • Radio profile changes cancel queued targeted work before Dispatcher can start it. In-flight ownership remains with Dispatcher. A late first discovery can cancel an unsent discovery retry. Matching late PATHs cannot restart a closed transaction or create reciprocal traffic.
    • The production scope/peer adapter is instantiated by native tests too. It adds at most three transient full-key peer contexts to the baseline bounded ACL search: current transaction and two retired contexts, all RAM-only. It does not change the sensor ACL or management route arrays.
    • The sensor has no other outbound RESPONSE/PATH request owner. Its custom binding consumes unowned RESPONSE/PATH messages rather than installing them as management routes, including responses older than the transient peer ring. Normal non-response management PATH and authenticated request callbacks keep their existing runtime owner. This policy is confined to the custom adapter.
    • The generic Mesh PATH decoder now checks that the encoded path plus its extra-type byte fits inside the authenticated decrypted payload before reading either extra fields or invoking a callback. A valid encoding with truncated content is rejected; no bot policy was added to core.
    • Reports/discovery keep their original channel, scope key and hash width. Intervening traffic or default-scope changes do not redirect the transaction. Candidate routes must come from fresh authenticated responses; recent four-entry history ranks them but cannot invent a route. Targeted history includes the full target key, full scope key, channel and radio profile, and cannot borrow bare-trace evidence. History expires after fifteen minutes.

    Short routing hashes remain hints rather than proof of per-hop identity. Cached ambiguity still displays a hash rather than a confident repeater name.

    The recorded summaries retain the full-suite and firmware results.

    The new suite has 49 cases covering parser rejection, case folding, unknown and ambiguous prefixes, actual request/response cryptography, colliding peer hashes and full ACL search capacity, RTC tags, all route lengths/hash widths, bounded queue/start/allocation failures, wrong tag/MAC/scope, configuration cancellation, late replies and new-target ownership, alternate retries, paired-SNR fallback, management ACL preservation and ordinary admin request callbacks. It also checks wrap-safe discovery clocks and separation of full-target history.

    Six additional packet-medium cases exercise actual forwarding plus a known-client/replay-protected repeater responder: selected-target discovery, loop and report on both channels and both widths through scoped-only relays; unknown-client timeout without login; and correct RTC replay-counter handling. The existing bare trace, scope, averaged SNR, storage and policy suites pass.

    The existing CI test_sensor_* filter and sanitizer inheritance select the new suite automatically. ASan uses the same temporary local Fedora runtime and isolated configuration described in the scope validation:

    ASAN_OPTIONS=detect_leaks=0 pio test \
  -c /tmp/meshcore-scope-asan.ini -e native_sensor_asan

    No repository sanitizer flags were changed. These are local CI-equivalent runs, not a claim of remote CI execution. Firmware keeps its existing -w flag; MkDocs retains the existing FAQ missing-anchor INFO notice without failing strict validation.

    Not run. No device was flashed.
